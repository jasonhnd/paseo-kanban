部署、构建、搬数据、发布演练、运维及任何长于几分钟的命令，要么用一条前台命令阻塞到结束并给足 timeout，要么登记看板托管的后台等待。前台长命令需要等待结果时，每次等待 yield_time_ms ≥300000（或工具等价参数），不要短间隔反复查看；也可拆段，每段一次阻塞跑完。禁止反复调用 wait/sleep 或每分钟轮询进度：每次工具返回都可能再触发一次昂贵的模型调用。工具不能阻塞到任务结束时，使用后台方式。
后台用法：在本卡 KANBAN_TMP 内选新路径，启动脱离终端的 shell，把输出重定向到 "$KANBAN_TMP/job.log"；执行命令后将退出码写入 "$KANBAN_TMP/job.exit.pending"，再原子重命名为 "$KANBAN_TMP/job.exit"。例如 `nohup sh -c 'your-command; rc=$?; printf "%s\n" "$rc" > "$KANBAN_TMP/job.exit.pending"; mv "$KANBAN_TMP/job.exit.pending" "$KANBAN_TMP/job.exit"' > "$KANBAN_TMP/job.log" 2>&1 < /dev/null & job_pid=$!`（替换 your-command，先清理旧标记，写退出码的外层不要用 set -e）。在同一次 shell 调用中立即运行 `paseo-kanban wait-bg "$KANBAN_TMP/job.exit" --card <卡号> --pid "$job_pid" --log "$KANBAN_TMP/job.log"`。登记成功后结束本回合。卡片显示「等后台任务」，由看板服务检查标记，不调用模型，结束时携退出码和有界日志尾部唤醒原 agent 一次。看板重启后可恢复，重试沿用同一去重凭据；看板服务必须保持运行。仅有 Codex 后台会话或 Claude ScheduleWakeup 不算登记唤醒。登记失败须先修好再结束回合。必填 --pid 指向负责写退出码标记的 shell，必须属于当前用户且为调用 shell 的后代或同会话进程；登记时保存进程组与启动时间，防止 PID 复用。缺标记只在该进程存活且未超时时继续等待；进程死亡未写标记或超过墙钟时限会携错误与最多 8 KiB 日志尾唤醒一次，超时不杀进程。睡眠计入时限，唤醒或重启后第一个 tick 立即复查。默认三小时，可用全局／项目配置 backgroundWaitMaxMs 或单次 --timeout-ms 覆盖。标记格式错误或临时目录被替换时也携错误唤醒。所属 leader 可用 unblock 取消。后台 shell 必须脱离终端并能在本回合结束后存活。
