For deployments, builds, data moves, release rehearsals, operations and any command lasting more than a few minutes, use one foreground command that blocks until completion with a sufficient timeout, or register a board-managed background wait. When waiting for a long foreground command, each wait must set yield_time_ms >=300000 (or the tool's equivalent); do not recheck at short intervals. Alternatively, split the work into stages and run each stage in one blocking call. Do not repeatedly call wait/sleep or poll progress every minute: each tool return can start another expensive model call. If the tool cannot block for the full duration, use the background option.
Background usage: choose fresh paths under this card's KANBAN_TMP, start a detached shell that redirects output to "$KANBAN_TMP/job.log", runs the command, saves its exit code to "$KANBAN_TMP/job.exit.pending", then atomically renames that file to "$KANBAN_TMP/job.exit". For example, run `nohup sh -c 'your-command; rc=$?; printf "%s\n" "$rc" > "$KANBAN_TMP/job.exit.pending"; mv "$KANBAN_TMP/job.exit.pending" "$KANBAN_TMP/job.exit"' > "$KANBAN_TMP/job.log" 2>&1 < /dev/null & job_pid=$!` (replace your-command, remove stale markers first, and do not use set -e around the exit-code write). In the same shell invocation, immediately run `paseo-kanban wait-bg "$KANBAN_TMP/job.exit" --card <card> --pid "$job_pid" --log "$KANBAN_TMP/job.log"`. After registration succeeds, end this turn. The card shows "Waiting for background task"; the board service checks the marker without calling the model and wakes the original agent once with the exit code and bounded log tail. This survives board restarts and retries with the same receipt. The board must be running. Plain Codex background sessions and Claude ScheduleWakeup alone do not register a wake. If registration fails, fix it before ending the turn. The required --pid identifies the marker-writing shell, must be owned by the current user and descended from the invoking shell or in its session, and is saved with its process group and start time to detect PID reuse. A missing marker waits only while that process lives and the wall-clock limit has not expired. Process death without a marker or timeout wakes you once with an error and at most 8 KiB of log tail; timeout does not kill the process. Sleep counts toward the limit and the first tick after wake or restart rechecks it. The default is three hours; backgroundWaitMaxMs in global/project config or --timeout-ms for this wait overrides it. A malformed marker or replaced temporary directory also wakes you with an error. A scoped leader can cancel with unblock. The detached shell must survive the turn ending.
