For deployments, builds, data moves, release rehearsals, operations and any command lasting more than a few minutes, use one foreground command that blocks until completion with a sufficient timeout, or register a board-managed background wait. Do not repeatedly call wait/sleep or poll progress every minute: each tool return can start another expensive model call. If the tool cannot block for the full duration, use the background option.
Background usage: choose fresh paths under this card's KANBAN_TMP, start a detached shell that redirects output to "$KANBAN_TMP/job.log", runs the command, saves its exit code to "$KANBAN_TMP/job.exit.pending", then atomically renames that file to "$KANBAN_TMP/job.exit". For example, run `nohup sh -c 'your-command; rc=$?; printf "%s\n" "$rc" > "$KANBAN_TMP/job.exit.pending"; mv "$KANBAN_TMP/job.exit.pending" "$KANBAN_TMP/job.exit"' > "$KANBAN_TMP/job.log" 2>&1 < /dev/null &` (replace your-command, remove stale markers first, and do not use set -e around the exit-code write). Then run `paseo-kanban wait-bg "$KANBAN_TMP/job.exit" --card <card> --log "$KANBAN_TMP/job.log"`. After registration succeeds, end this turn. The card shows "Waiting for background task"; the board service checks the marker without calling the model and wakes the original agent once with the exit code and bounded log tail. This survives board restarts and retries with the same receipt. The board must be running. Plain Codex background sessions and Claude ScheduleWakeup alone do not register a wake. If registration fails, fix it before ending the turn. A missing marker keeps waiting; a malformed marker or replaced temporary directory wakes you with an error. A scoped leader can cancel with unblock. The detached shell must survive the turn ending.
