# Security policy

Do not disclose credentials, exploit details involving private data, real databases, full host configuration or sensitive logs in public issues, pull requests or discussions.

The intended private disclosure channel is **GitHub private vulnerability reporting** for this repository: open the Security tab and choose **Report a vulnerability** when available. The repository owner must enable this feature before public release. This document does not assert that it has already been enabled. If the button is unavailable, do not publish the sensitive details; wait for a private reporting channel to be made available. No email address or response deadline is promised.

In a private report, include the affected plugin/companion versions, OS and Paseo versions, install source, impact and a minimal demo reproduction. Redact authentication material and personal identifiers even in private reports. Coordinate public disclosure with the owner after assessment and remediation.

The project is experimental. Security fixes and supported versions are recorded in CHANGELOG Security and Notes sections; there is no long-term support or guaranteed remediation schedule. Publishing a tag does not establish stability. See [the release prerequisites](docs/RELEASE.md).

Dispatch limits for the official Antigravity ACP entry are recorded in [Antigravity authorization](docs/ANTIGRAVITY-AUTHORIZATION.md). That record does not enable the entry.
