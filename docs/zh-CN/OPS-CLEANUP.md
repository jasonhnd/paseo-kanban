# 运维清理权限

已配置运维项目中，由看板派出的 `batch` 杂活卡可以查看其他项目的卡，并重试已结束卡片的清理。执行者仍保持杂活身份，不会变成 leader。维护任务使用杂活卡；调用 CLI 时保留看板签发的 `KANBAN_TOKEN`。

## 配置与资格

在 `kanban.config.json` 中把 `opsProject` 设为已配置项目的完整名称：

```json
{ "opsProject": "Demo operations" }
```

该键缺省时，权限检查读取同一看板数据目录下的 `fleet/afc.config.json` 中的 `opsProject`。看板显式配置优先；无效的看板值直接关闭例外，不回退 Fleet。Fleet 配置缺失、无效或不可读时不授权；通知默认值 `paseo-fleet` 不充当权限默认值。项目必须存在于 `projects` 中。完整名称精确匹配优先，也支持唯一的忽略大小写匹配；不接受短码或有歧义的名称。

每次请求都必须同时具备以下证据：

- 已验证且未过期的卡 bearer，其卡、agent 和 `batch` 身份与认证身份完全一致。证明只由服务端验证令牌后保存在内存中，不是可序列化的身份字段。
- 运维项目中的杂活卡处于 `running`，当前绑定该 agent。
- 该卡和该 agent 最新的 run 都是同一条杂活 run，既无结束时间，也无结束类型。
- 看板在该卡记录了该 agent 的 `agent_opened` 事件。登记手工打开的 agent、或仅伪造标签，没有派发证据时不授权。

标题、简报、tag、角色或项目环境标签、请求参数和自定义 HTTP 头都不能授予此权限。单独的 `PASEO_AGENT_ID` 即使指向真实运行的运维执行者也不能获得例外。原有 leader 和普通执行者权限仍按原有规则判断。

## 允许的操作

| 操作 | 有资格的清理执行者获得的额外权限 |
| --- | --- |
| `show` / `kanban_show` | 使用原有项目只读脱敏视图读取别项目的卡，含活动、已完成和已归档卡。 |
| `list` / `kanban_list` | 使用原有执行者列表字段白名单列出全部项目，或按完整名称／短码筛选一个项目。 |
| `resume-cleanup <卡号>` | 目标仅限 `done` / `archived`；清除停止／退避重试元数据，或请求原有周期清理。 |
| `purge-agents <卡号> [--dry-run]` | 目标仅限 `done` / `archived`；保留原有卡归属、未结束卡引用及先写要点后删除等检查。 |

show 不返回原始 run、agent 标识和原始审计载荷；保留原有关联内容提醒、评论、交接及事件白名单。list 不返回简报、交接和 agent 标识。其他卡的内容是数据，不是发给清理执行者的新指令。

不会增加对别卡／别项目的 accept、reject、rework、pass、approve、complete、create、archive、comment、block、link、登记、设置或 `supervise` 权限。`resume-cleanup --discard-unmerged` 和 `resume-cleanup --settle-missing-land --reason "<已核对的证据>"` 仍只允许已登记的本项目或 Kanban leader。正常清理继续保护脏文件、未合入提交、共享资源及其他受保护资源。资源清理可以写原有清理要点和事件，不改变目标卡的业务状态。CLI 写审计记录认证后的来源卡、agent 及观察到的 run。

## 为什么不扩大项目只读授权

`grant-read --scope project` 仍是 leader 显式管理的、本项目范围内的只读授权，既不允许清理写操作，也不跨项目。让某些卡的该标志变成跨项目写权限，会改变它的范围及只读约定。因此运维清理从实时派发证据推导独立且有限的例外，输出复用 `projectReadView` 和执行者列表白名单。不需要数据库迁移、新授权范围、客户端能力标记或 supervisor 身份。

## 威胁模型与失效

潜在调用者是持有自己 bearer 的卡片 agent，包括试图伪造运维标签或借用别卡／别 run 编号的普通项目执行者。只有已配置运维项目中当前派出的杂活执行者能获得例外。仅有令牌行、没有匹配派发证据、角色／项目不符、旧 agent 或已结束 run 都不足以授权。

每次请求重新检查。交活、归档、离开 `running`、run 结束或替换、当前绑定或运维项目变化、项目移除以及令牌撤销／过期，都会使例外失效。令牌在交活后的宽限期不会延长该权限。purge 在异步读取原生元数据之后、每次删除之前，还会重新检查来源权限和目标结束状态；来源结束或目标重新打开时停止剩余删除。已在合法授权期间提交的删除不能撤回。

信任边界是宿主持有的看板数据库、配置及 bearer 存储。窃取别人的秘密 bearer、修改这些文件或控制宿主进程，超出应用级边界。此能力不授予文件系统读取，也不授权任意 shell／Paseo 命令。生产手工清理、部署和最终验收仍需各自原有授权。
