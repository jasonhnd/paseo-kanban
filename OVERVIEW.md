# Paseo Kanban

Paseo Kanban combines a cross-project coding-agent board with Fleet roles, quota, decisions and settings in one sidebar entry. Cards have a role and difficulty tier. Executors hand work to a reviewer with a different confirmed actual model, then the project leader accepts it. Different models in one family are allowed; an identical normalized model across providers or settings is refused.

Fleet supplies an immutable policy revision for dispatch. Missing or invalid policy, unresolved model evidence and unknown protected quota readings hold dispatch. You configure project workspaces, role profiles, pools and their quota sources. Profile setup previews a catalog; it does not save profiles or prove provider login. Local providers must be installed and authenticated by you.

The experimental 0.1 source declares Paseo daemon and app versions `>=0.11.0 <0.12.0`. The current command/compiler baseline is 0.11.2. The daemon host needs Node >=24.21.0 with `node:sqlite`, Git and npm. macOS has local toolchain evidence and actual isolated official 0.11.2 Web UI checks in Microsoft Edge. The native app, physical phones, Linux/WSL2 and an authenticated provider first-card cycle remain unverified. Native Windows is not supported for the initial release. The declared host range and a successful build are not full platform certification.

Plugins are trusted and unsandboxed. Preparation installs locked npm dependencies and builds command bundles on the daemon host. Server code operates configured repositories, workspaces and agents through Paseo and local Git, Node and provider processes. Card briefs and task context go to the selected provider through those agents. Quota collection can ask Paseo for provider usage and, for configured sources, invoke local usage tools. GitHub and the daemon host's npm registry are contacted for installation or updates; provider tools may contact their own services.

Optional adapters are controlled by `fleet/afc.config.json`. Fresh data roots start with `cursor-api`, `keychain` and `antigravity-cli` off. For existing state, an unset Cursor or keychain switch can stay on when its previous state marker exists; explicit `false` overrides that inheritance. Antigravity always needs explicit `true` and a matching plan. Enabled Cursor access uses the plugin's own user-authorized login to send authentication and usage/login requests to `cursor.com` and `api2.cursor.sh`, with a configured local usage-screen fallback. The macOS keychain probe checks presence/status rather than requesting secret values. The Antigravity reader invokes local `agy` usage output; it does not establish that CLI and Paseo ACP consume the same quota pool. These features do not make credentials or raw local logs safe to share.

Board/Fleet configuration, decisions, SQLite state, audit/log files, policy snapshots, exports and plugin-owned secrets persist below `KANBAN_DATA_DIR`, or `PASEO_HOME/plugin-data/paseo-kanban` (Paseo home defaults to `~/.paseo`). Fleet uses the `fleet/` child. Host plugin settings are separate. Old Fleet storage overrides are configuration errors, and old data is not automatically imported. A managed code update or uninstall does not restore or reset that external data root. Back up consistent data and host settings separately before changing sources; see [data ownership](docs/DATA.md) and [compatibility](docs/COMPATIBILITY.md). Git distribution and official registry review are separate; this page does not declare a registry listing or completed production switch.
